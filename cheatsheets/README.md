# Cheatsheets and field references

Practical PDF references to keep beside a lab: find the relevant command, understand when it helps and decide what to check next.

**Build · Understand · Apply.** Use a sheet alongside your own evidence and reasoning, rather than treating a command or tool result as a conclusion.

## Choose a reference

| PDF | What it helps with |
|---|---|
| [Bash and Vim](bash-vim-reference.pdf) | Find your way around a Linux host, inspect evidence, filter output and edit files. |
| [Python](python-reference.pdf) | Build small tools and work with files, data and lab evidence. |
| [Windows](windows-reference.pdf) | Use PowerShell to inspect identity, services, processes and host evidence. |
| [Reconnaissance and enumeration](recon-enumeration-reference.pdf) | Move from scope and discovery to manual validation and the next useful check. |
| [SQL injection and SQLMap](sql-injection-sqlmap-reference.pdf) | Follow query context, database-specific syntax and controlled SQLMap checks. |

Open a PDF above to preview it on GitHub, then use the download button to save a local copy. These files are also included when you clone or download this repository. No account or running app is needed to read the downloaded PDFs.

## Use alongside the labs

- Start with [enumeration methodology](../methodology/enumeration-methodology.md) or [G5Labs workbooks](../G5Labs/README.md) when you need a guided exercise.
- Keep target, purpose, command, observation and interpretation in your lab notes; the cheatsheets are references rather than worksheets.
- Replace placeholders and check the shell, database and permissions expected by each command. SQL dialect labels identify applicability; they are not part of the payload.
- Practise against systems you own or have explicit permission to test. Results need context and manual validation.
